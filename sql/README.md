# SQL-слой

Девять запросов на SQLite, которые независимо от Python воспроизводят контрольные цифры проекта из исходных таблиц.

| Файл | Что считает | Ожидается (исправленные данные) |
|---|---|---|
| 01_revenue_erp | выручка по ERP | 825 211 700 ₽ |
| 02_revenue_1c | выручка по проводкам 1С | 825 211 796 ₽ |
| 03_reconcile_erp_1c | сверка ERP и 1С по клиникам и месяцам | 0 существенных расхождений (на «грязных» данных 10) |
| 04_profit_before_tax | прибыль до налога из проводок | 158 046 155,89 ₽ |
| 05_cash_end_of_year | остаток денег на конец года: ОСВ, ДДС, проводки | 216 038 096,87 ₽ |
| 06_min_daily_balance | остаток по дням, минимум за год (оконная функция) | 16 579 356 ₽, 10 января |
| 07_stress_insurer_delay | стресс: задержка страховых 30 дней | остаток на конец года 204 579 396,87 ₽ |
| 08_new_patients_ltv | новые пациенты, январская когорта, LTV за 12 месяцев | 27 924; 1 287; 34 101,48 ₽ |
| 09_doctors_coverage | врачи, врач-месяцы, визиты без врача | 43; 479; 0 |

## Запуск
`python src/sql/run_sql.py` собирает базы `data/sql/corrected.db` и `data/sql/dirty.db` из CSV и сверяет результаты (31 проверка).
Любой запрос можно открыть и запустить отдельно в DB Browser for SQLite на `data/sql/corrected.db`.

## Что важно знать
- Номера счетов хранятся как текст. Иначе `90.01` становится числом и теряется.
- Выручка в SQLite хранится целой, поэтому деление требует `1.0 *` (иначе целочисленное деление; на этом запрос 8 сначала ошибся: 34 101 вместо 34 101,48).
- Ожидаемые значения по «corrected» совпадают с книгами проекта и таблицей контролей. Значения по «dirty» зафиксированы по результату запуска и показывают, что запросы ловят дефекты, независимым контролем они не являются.
